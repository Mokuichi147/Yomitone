# Jev 互換バックエンドの実機検証

検証日: 2026年11月4日（日本時間）  
対象: `http://192.168.11.51:11433` / `clef-artemis`  
検証開始時のコミット: `ec6665807ccf8e073c9871089cb31daec0de68c4`

**最新の実小説による検証は [REAL_EVALUATION.md](REAL_EVALUATION.md) を参照。** 論理・物理バッチ8192でAPIエラーは解消したが、実小説1章の話者推測は既定設定で48/59正解（81.4%）、後続2行で46/59正解（78.0%）だった。無確認での自動読み分けには精度の課題が残る。人物一覧は事前に用意した条件であり、人物抽出からの実行は指定構成では停止する。

バッチ・並列数の比較は [TUNING.md](TUNING.md)。その成績は自作評価文での結果であり、実小説の正答率とは区別する。

指定のモデルを指定のサーバーで使用した Jev 互換 API の検証であり、TypeSafe が提供する Jev モデル自体の性能を測定したものではない。初回検証では製品コード・サーバー設定を変更せず、追加検証で指定モデルのロード設定を変更した。製品コードは変更していない。

並列実行の影響を追加で確認し、送信側の並列数1・HTTP要求1件・再試行0回でも、649トークンの自作入力に対して同じ500エラーが約0.025秒で返ることを確認した。記録は `results/recheck/single-request.json`。前回までの検証も1件ずつ順次送信しており、再試行は前の応答が返った後に行っている。

同じエラー文を返す [llama.cpp の実装](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/server-context.cpp) では、分割できない入力のトークン数が物理バッチ上限 `n_ubatch` を超えると拒否する。`--parallel` はサーバーのスロット数、`--ubatch-size` は物理バッチ上限という別設定である（[公式サーバー資料](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md)）。接続先の実際のサーバー並列数・ビルド・他クライアントの利用状況は未確認であり、それらの影響全体を否定する検証ではない。

## 測定方法

- `JevSpeakerEstimator` と `SpeakerEstimation` をそのまま呼び出す Rust の検証用 example を追加。自作の35セリフ・9シナリオを、既定の履歴100行・後続0行で2回実行した。過去の推測結果は実際の処理と同じく次のセリフに引き継いだ。
- 人物一覧を固定した条件で、推測処理単体を評価した。後続2行を渡す比較も1回実施した。
- 自作の長い履歴を用い、履歴100行と2行を比較した。
- 自作の2章の入力を、登場人物抽出から実際の CLI で処理した。
- 送信許可を得た実データ1章・59セリフも評価した。本文、人物情報、元ファイル名、正解ラベル、個別の推測結果は保存せず、集計値だけを残した。
- 複数の検証処理から同時に推論を走らせず、各測定を順に実行した。計測時間にはネットワークとアプリの再試行を含む。

同じ35セリフの反復は独立した70例ではない。自作の会話は比較的明瞭であり、正答率を一般の小説全体に外挿できない。地の文は自動でナレーターになるため、正答率の分母に含めていない。

| 分類 | 正答 |
| --- | --- |
| 明示された話者 | 8/8 |
| 二人が交互に話す短い応答 | 12/12 |

後置の話者説明は後続2行を渡すと4/4正解になった。一方、引用を含む会話に新しい誤りが1件発生しており、後続行を増やすだけで常に正しくなるとはいえない。後続行数は現在のCLI・GUIから設定できず、比較ではコアの公開設定を変更した。

## 確認した問題

### 1. 登場人物抽出に使うAPIが失敗する

指定の `/v1/models` には `clef-artemis` が存在し、`/v1/systemone` で推測に成功する。一方、登場人物抽出用の `/v1/chat/completions` は次のエラーを返した。

```text
400: No models loaded. Please load a model in the developer page or use the 'lms load' command.
```

自作の2章を処理する実CLIはこのエラーで終了コード1になり、話者推測に進まなかった。モデル一覧に名前があることだけでは、抽出用APIで使用できることを確認できない。

実データでも抽出が同じ理由で失敗した。抽出に約0.017秒を要し、人物一覧は取得できなかった。抽出段階の失敗なので、この条件での話者推測の正答率は算出していない。集計値は `results/real-default-summary.json` に保存した。

### 2. physical batch size 512 による入力制限

13候補の短い会話でも、649〜727トークンの入力で次のサーバーエラーを返した。

```text
500 clef-artemis: input (649 tokens) is too large to process.
increase the physical batch size (current batch size: 512)
```

履歴100行の自作文では、履歴だけで約7,600文字、要求全体で5,746〜5,785トークンとなり、2件とも失敗した。同じ入力で履歴を2行に制限すると2件とも成功した。

実データでも、正しい人物一覧を別途与え、履歴を4行に制限して59セリフを検証した。59件すべてが同じバッチサイズのエラーになり、ナレーターへ切り替わった。処理時間は約91.7秒。人物情報やセリフ自体も入力の長さに含まれるため、履歴を短くするだけでは現在の上限を回避できなかった。モデルの意味理解を採点できる有効な応答は0件だった。集計値は `results/real-short-summary.json` に保存した。

Yomitone は500を再試行するが、入力を短くするのは413、または入力長超過を示す400/422の場合である。この500では同じ要求を初回と再試行2回送り、約1.6秒後にナレーターへ切り替える。人物や説明文だけで上限を超える場合は、履歴の短縮だけでは解消できない。

### 3. GUIのJev接続確認と実際の推測が一致しない

サーバーのモデル一覧は OpenAI 形式の `data[].id`。Jev アダプターの `list_models()` は `models[].name` を期待するため、次のエラーになる。

```text
GET http://192.168.11.51:11433/v1/models: 200 Invalid response data: models
```

実際の話者推測に成功しても、GUIのJev設定では接続失敗と表示される。各結果JSONの `model_list_error` に記録している。

### 4. 低確信度でも読み分けに採用する

既定の自作評価文では、APIが返した誤答4件の確信度は約0.41〜0.49だった。現在は確信度を表示するだけで、そのまま人物に割り当てる。

同じ評価文で確信度0.5以上だけを残すと58/70件を採用し、その58件はすべて正解だった。ただし、実データでは人物抽出が失敗しており、この結果から本番の閾値を決めることはできない。確信度は正答率そのものでもない。[TypeSafe公式の確信度説明](https://docs.typesafe.ai/confidence)

## 実用化するための優先事項

1. 指定モデルで `/v1/chat/completions` による人物抽出が成功するサーバー状態・モデル対応を確認する。Jev の話者推測APIが成功するだけでは、一連の処理は動かない。
2. 想定する人物一覧・履歴の入力全体を処理できるよう、サーバーの physical batch size を拡大する。確認した長文ケースでは約5,800トークンが必要だった。GPUメモリやモデルの制限もあるため、設定変更後の再計測が必要。
3. サーバーが入力超過に500を返す挙動と、アプリの再試行・縮小・失敗通知を整合させる。大量の切り替えが発生しても通常完了に見える状態を避ける。
4. モデル一覧の OpenAI 形式にも対応するか、推測用の短い実リクエストで接続を確認する。
5. 後続文脈、履歴のトークン量、低確信度の扱いを評価データで調整し、複数作品・複数章で再評価する。

初回検証ではサーバー設定や製品コードを修正していない。TTSサーバーは指定されていないため、実音声の合成・音質は評価対象に含めない。

## 再実行

リポジトリのルートで実行する。認証を要求しないローカルサーバーには検証用のダミーキーを渡す。実際のキーが必要なサーバーでは `TYPESAFE_API_KEY` を環境変数に設定する。

```bash
cargo run --offline -p yomitone --example evaluate_jev -- \
  evaluations/jev/synthetic.json evaluations/jev/results/synthetic-default.json \
  http://192.168.11.51:11433 clef-artemis jev 0 2 fixed

cargo run --offline -p yomitone --example evaluate_jev -- \
  evaluations/jev/synthetic.json evaluations/jev/results/synthetic-following2.json \
  http://192.168.11.51:11433 clef-artemis jev 2 1 fixed

cargo run --offline -p yomitone --example evaluate_jev -- \
  evaluations/jev/long.json evaluations/jev/results/long-default.json \
  http://192.168.11.51:11433 clef-artemis jev 0 1 fixed

cargo run --offline -p yomitone --example evaluate_jev -- \
  evaluations/jev/long.json evaluations/jev/results/long-previous2.json \
  http://192.168.11.51:11433 clef-artemis jev 0 1 fixed 2

python3 evaluations/jev/summarize.py evaluations/jev/results/synthetic-default.json

cargo run --offline -p yomitone-cli -- \
  --host 192.168.11.51 --port 11433 --model clef-artemis \
  --speaker-backend jev --jev-base-url http://192.168.11.51:11433 \
  --jev-model clef-artemis --jev-api-key local-evaluation evaluations/jev/cli-input
```

example の引数は順に、ケースJSON、結果JSON、URL、モデル、バックエンド（`jev` / `llm`）、後続行数、反復数、人物一覧（`fixed` / `extract`）、任意の履歴行数（既定100）。`extract` では指定サーバーの OpenAI 互換APIで人物を抽出する。コア本体と同様に、致命的な抽出エラーではそのケースの推測を実行しない。正答率には未処理・推測失敗も含める。ケースごとに結果を保存する。

実データについてはプライバシーの指定により再実行用の参照情報・正解ラベルを残していない。本文・人物情報・元ファイル名が追加成果物に含まれないことを検査し、非公開の参照情報と詳細結果の一時ファイルも削除した。結果JSONは実測時の記録であり、再実行すると上書きされる。
