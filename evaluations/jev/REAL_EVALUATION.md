# 実小説による話者推測の検証

検証日: 2026年11月4日（日本時間）  
モデル: `clef-artemis`  
接続先: `http://192.168.11.51:11433`

**実小説1章では、既定設定で59セリフ中48件正解（81.4%）だった。APIエラーは解消したが、声の誤割当が多く、無確認での自動読み分けには不十分だった。後続2行を渡しても46/59（78.0%）へ悪化した。** 自作評価文の94.3%だけでは、この小説での実用性を判断できなかった。

## 条件

- ユーザーが送信を許可した手元の小説1章を使用した。59セリフすべてに、本文を読んで決めた正解ラベルを用意した。
- 人物名・別名・性別と、本文から採った短い説明を事前指定した。ナレーターを含む候補は6件。人物抽出を含めず、話者推測単体を評価した条件である。
- 実際の `JevSpeakerEstimator` と `SpeakerEstimation` を使用した。1件ずつ処理し、直前の推測結果を次のセリフの履歴へ引き継いだ。正しい履歴で各問を独立に解くベンチマークとは異なる。
- 履歴100行・後続0行が既定設定。地の文と空行も実際の入力と同じく履歴の行数に含まれる。
- 論理バッチ8192、物理バッチ8192、サーバー並列上限4、コンテキスト長262144でロードされていることをAPIで確認した。
- 本文・人物情報・元ファイル名・正解ラベル・個別の推測結果は一時領域だけで扱い、成果物には集計値だけを保存する。

## 既定設定の結果

| 項目 | 結果 |
| --- | --- |
| 全セリフの正答 | **48/59（81.4%）** |
| 読み上げる文字を含むセリフの正答 | **48/58（82.8%）** |
| API失敗によるナレーターへの切り替え | **0件** |
| 合計処理時間 | **約169.3秒** |
| 1セリフの平均 / 中央値 / p95 | **2.87 / 3.22 / 3.42秒** |

59件には記号だけのセリフが1件含まれる。これは音声合成時に読み飛ばされるため、実際に音声が出る58件の精度も別に示した。音声が出るセリフでは10件の話者を取り違えており、およそ6セリフに1回の割合になる。

この章を処理できることは確認できたが、APIが正常応答することと、声を正しく読み分けることは別の評価になる。

誤答11件はすべて、別の登場人物を選んだ誤りだった。ナレーターへの切り替えや通信失敗によるものではない。

## 後続2行を渡した比較

人物一覧・正解ラベル・履歴100行・処理順をそろえ、後続行数だけを変更して章全体を再処理した。どちらも前の推測結果を履歴へ引き継ぐ。

| 項目 | 後続0行（既定） | 後続2行 |
| --- | --- | --- |
| 全セリフの正答 | **48/59（81.4%）** | **46/59（78.0%）** |
| 読み上げる文字を含むセリフの正答 | 48/58（82.8%） | 46/58（79.3%） |
| API失敗 | 0件 | 0件 |
| 合計処理時間 | 169.3秒 | 172.3秒 |
| 平均 / 中央値 / p95 | 2.87 / 3.22 / 3.42秒 | 2.92 / 3.24 / 3.53秒 |

2件の誤りが直った一方、正しかった4件に新しい誤りが発生し、9件は両条件で誤っていた。自作評価文で後置の説明を渡すと改善したことから、実小説全体でも精度が上がるとはいえなかった。

これは1章に対する探索的な比較であり、別作品でも後続2行が悪化を招くと断定するものではない。現行CLI・GUIには後続行数の設定項目がないため、この比較ではコアの公開設定を変更した。

## 確信度による確認対象の選別

既定設定の59件に対する事後集計。アプリの振る舞いを変更して実行した結果ではない。

| 採用する確信度 | 採用件数 | そのうち正解 | 採用せず確認する件数 |
| --- | --- | --- | --- |
| 0.5以上 | 45 | 42（93.3%） | 14 |
| 0.7以上 | 39 | 38（97.4%） | 20 |
| 0.9以上 | 6 | 6（100%） | 53 |

確信度0.7以上に限定しても誤りが1件残り、全体の約3分の1を確認する必要がある。今回の1章だけで汎用的な閾値を決めることはできない。現行アプリは確信度を表示するだけで、これによる採用制限は行わない。

## 評価の範囲

人物一覧は事前に与えているため、この精度を人物抽出からの自動実行の精度として扱うことはできない。

同じ実小説で人物抽出からの実行も確認した。指定モデルを `/v1/chat/completions` に使うと `400: No models loaded` となり、人物抽出の段階で処理が中断した。話者推測への要求は0件だった。モデル管理APIではこのモデルは `decision` 型として提供されている。指定構成だけで人物抽出からの自動処理が動くことは確認できていない。

評価対象は、現行アプリが扱う行全体が `「」` で囲まれたセリフ。本文には地の文内に引用がある行も4行あり、これらは仕様上話者推測の対象外である。引用を含むすべての行が独立した発話とは限らない。

1作品の1章の結果であり、別の作品や後の章への精度を保証しない。TTSによる実音声の音質は今回の検証に含めない。

集計値:

- `results/real-8192/default-summary.json`: 既定設定
- `results/real-8192/following2-summary.json`: 後続2行
- `results/real-8192/comparison-summary.json`: 改善・悪化件数
- `results/real-8192/extraction-summary.json`: 人物抽出からの実行確認

プライバシーの指定により、本文・人物一覧・正解ラベルを含む再実行用データはリポジトリに残さない。

追加成果物に本文・人物情報・元ファイル名が含まれないことを検査し、入力参照・人物一覧・正解ラベル・個別結果の一時ファイルを削除した。製品コードはこの実データ検証のために変更していない。
